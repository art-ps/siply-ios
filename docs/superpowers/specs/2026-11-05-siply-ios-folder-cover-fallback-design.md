# Siply для iPhone — обложка папки вместо ноты

## Зачем

У многих альбомов обложка лежит файлом `cover.jpg` рядом с треками, а в самих треках картинки нет. Шапка папки её показывает, а строки треков, мини-плеер, полноэкранный плеер, экран блокировки и живой фон показывают ноту. Пользователь хочет: нет своей картинки у файла — берём картинку папки. Везде, включая строки списка треков («без нот»).

## Решено с пользователем

- Фолбэк — картинка папки. Показывается в строках треков, мини-плеере, полноэкранном плеере, на экране блокировки и в цветах живого фона.
- Своя картинка у трека важнее картинки папки.

## Что делаем

Одно правило в одном месте — `LibraryScanner`; весь UI и экран блокировки уже читают `track.artwork`.

1. `LibraryScanner.coverFile(in folder: URL) -> Data?` — вынести из `folderArtwork` поиск `cover.jpg` / `cover.png` / `folder.jpg` (порядок тот же, не скачанный из iCloud — пропускаем, как сейчас). Читать `Data(contentsOf:options: .mappedIfSafe)`: у 30 треков одной папки одна и та же картинка не копируется 30 раз в память.
2. `loadTrack(_:)`: после чтения тегов, если `artwork == nil`, — `coverFile(in: url.deletingLastPathComponent())`.
3. `tracks(in:)`: строки-заглушки без тегов (`.remote`, `.onDemand`) тоже получают `coverFile(in: folder)` — серые и SMB-строки с обложкой.
4. `FileTrackLoader` (восстановление очереди после перезапуска): заглушки `.remote` / `.onDemand` — так же.
5. `folderArtwork` остаётся: первый трек с картинкой, иначе `coverFile`. Моё решение: в смешанной папке (у трека 1 нет картинки, у трека 3 есть, рядом лежит `cover.jpg`) шапка теперь покажет `cover.jpg`, а не картинку трека 3, — первый трек уже несёт её как фолбэк. Это ближе к «картинке папки».

## Критерии приёмки (тесты)

`LibraryScannerTests`:
- `loadTrack_noEmbeddedArt_usesCoverFile`: WAV без тегов + `cover.jpg` (байты `[1,2,3]`) в той же папке → `artwork == Data([1,2,3])`.
- `loadTrack_noEmbeddedArt_noCover_nil`: WAV без `cover.jpg` → `artwork == nil`.
- `coverFile_order`: есть `cover.png` и `folder.jpg` → берётся `cover.png`; нет ни одного → `nil`.
- `tracks_onDemandPlaceholders_getCover`: `tracksOnDemand: true`, два WAV + `cover.jpg` → у обоих `artwork == cover`.
- Существующий `testFolderArtworkPrefersTrackArtworkThenCoverFile` остаётся зелёным.

`FileTrackLoaderTests`:
- `onDemandPlaceholder_getsCover`: файл вне папки приложения + `cover.jpg` рядом → заглушка с `artwork == cover`.

Ручная проверка (чеклист, пункт 16): папка с `cover.jpg` и треками без картинок → в строках, мини-плеере, плеере, на экране блокировки — обложка, фон плеера в её цветах; трек со своей картинкой — своя.

## Не делаем

- Поиск: строки результатов строятся без чтения тегов прямо в отрисовке; читать там файлы — тормозить главный поток. Трек, запущенный из поиска, остаётся с нотой, как сейчас без тегов.
- Картинки из подпапок, `front.jpg`, `albumart*.jpg` и прочие имена — только три текущих.
- Кэш картинок папок — `.mappedIfSafe` хватает.
