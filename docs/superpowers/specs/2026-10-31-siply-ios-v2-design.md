# Siply для iPhone — v2: продолжение, скорость, таймер сна, переименование, место на устройстве

## Зачем

v1 (`2026-10-30-siply-ios-design.md`) стоит на телефоне и работает. Пять мелких вещей, которых не хватает в быту: после перезапуска плеер пуст; аудиокниги слушаются на 1,25×, а скорости нет; засыпать под музыку нечем; подпапка «На iPhone» приходит с UUID вместо имени; скачанное из iCloud нельзя выгрузить, не удаляя из облака.

## Решено с пользователем

- Скорость воспроизведения **одна на всё приложение**, не по папкам. Пользователь слушает аудиокниги на 1,25.
- Позиция внутри файла и «последняя глава папки» **не запоминаются**: «Воспроизвести» в папке и тап по треку — всегда с начала. Единственное «продолжить с места» — восстановление последней сессии после перезапуска (п.1).
- Плавные переходы между треками — обсуждались, **отложены**. Не делаем.

## Что делаем

### 1. Продолжение после перезапуска

Закрыл приложение на 17-й минуте главы — открыл: в мини-плеере та же глава, на паузе, прогресс 17:00, очередь та же. Play — продолжает с 17:00.

- `PlayerModel` сохраняет `PlaybackState { urls: [String], currentIndex: Int, position: TimeInterval, shuffle: Bool }` в `UserDefaults` (ключ `playback`, JSON). Пути — абсолютные `url.path`; при переустановке контейнер меняется и состояние теряется — приемлемо. *Решение моё.*
- Когда сохраняем: пауза, смена трека, `seek`, уход приложения в фон (`scenePhase != .active`), и во время игры — не чаще раза в 5 с (из существующего таймера прогресса 0,5 с). Пустая очередь → ключ удаляется.
- Восстановление при запуске, после того как `SourceStore` восстановил bookmark'и (дочерние URL работают, пока открыт родитель): пути → URL; файл, которого нет (`fileExists`), выбрасывается из очереди. Если нет самого текущего файла — состояние не восстанавливается, плеер пуст. Для оставшихся — `Track` как в `LibraryScanner.tracks(in:)`: нескачанный → `.remote` по имени, скачанный → теги. Чтение тегов — в фоне, мини-плеер появляется, когда готово. *Решение моё.*
- Восстановление не удалось (текущего файла нет: флешка не вставлена, SMB офлайн) — ключ `playback` **не трогаем**: он перезапишется следующим сохранением непустой очереди. Повторной попытки после `refresh()` нет. *Решение моё.*
- Восстановленное состояние: очередь, текущий трек, `currentTime = position`, `isPlaying == false`; движок загрузил файл, если он `.local` (чтобы `duration` и ползунок были сразу). Текущий трек `.remote` → мини-плеер показывает его, play — скачивает и играет с начала (позиция не применяется, файла не было). *Решение моё.*
- Shuffle восстанавливается из состояния вместе с порядком обхода, пересобранным заново (`rebuildOrder`) — точный прежний порядок перемешки не нужен. *Решение моё.*

### 2. Таймер сна

- В Now Playing — кнопка-меню `moon.zzz`: «Выкл», «15 мин», «30 мин», «60 мин», «До конца трека». Активный таймер: иконка акцентного цвета и остаток `mm:ss` рядом (для «До конца трека» — без остатка).
- Срабатывание — пауза без затухания, таймер сбрасывается в «Выкл». «До конца трека» — когда текущий трек доиграл: пауза на первой секунде следующего не нужна, плеер остаётся на доигравшем треке в позиции 0 (как `halt()`), таймер «Выкл».
- Реализация: `PlayerModel.sleep: SleepOption` (`off | minutes(Int) | endOfTrack`), `sleepDeadline: Date?`. Проверка — из таймера прогресса (он идёт только пока играет; на паузе таймер сна не нужен — если пользователь поставил паузу сам, дедлайн просто пройдёт и сработает на следующем тике после play: пауза сразу. Это приемлемо). Между запусками не сохраняется. *Решение моё.*
- «До конца трека» перехватывает `trackFinished()` **до** логики повтора: при `repeatMode == .one`/`.all` тоже останавливаемся. *Решение моё.*
- Ручной `next()`/`previous()` при «До конца трека» — таймер остаётся и сработает на конце нового трека. *Решение моё.*

### 3. Переименование источника

- Долгое нажатие на источник (кроме «Siply») → контекстное меню «Переименовать» → `alert` с текстовым полем, предзаполнено текущим именем. Пустое или из пробелов — не применяется.
- `SourceStore.rename(_:to:)` меняет `name`, сохраняет в `UserDefaults`.
- Имя по умолчанию для папки, чьё `lastPathComponent` — UUID (подпапка «На iPhone», iOS 26 отдаёт её по id элемента): «Папка». Остальное — как в v1 (`displayName`).

### 4. Место на устройстве (iCloud)

Только для файлов с `isUbiquitousItem == true`; в своей папке, на флешке и у File Provider'ов (SMB, Яндекс.Диск) этих действий нет — там нечего выгружать.

- Свайп по треку (trailing): `.local` → «Удалить с устройства» (`FileManager.evictUbiquitousItem(at:)`; файл остаётся в iCloud; строка становится `.remote`, серая с облаком); `.remote` → «Скачать» (`startDownloadingUbiquitousItem`; строка `.downloading`, белеет по завершении — через существующий `watchDownloads()`, который надо уметь перезапустить, если он уже закончился). Без подтверждений: обратимо.
- Долгое нажатие на строку подпапки → контекстное меню «Скачать» / «Удалить с устройства» — для **прямых** аудиофайлов папки (как считается её серость; вложенные подпапки не трогаем). Оба пункта показываются, если в папке есть соответствующие файлы; папка серая/белая обновляется. Пункты меню считаются заранее в `reload()` в фоне вместе с серостью (`folderActions: [URL: Set<FileAction>]`), не при долгом нажатии — иначе листинг iCloud повис бы на главном потоке. Папка, которая сама `.remote` (iCloud-плейсхолдер, внутрь не заходим) → только «Скачать» = `startDownloadingUbiquitousItem(at: folder)`. *Решение моё.*
- Играющий сейчас трек не выгружается: если он в списке — пропускается. `PlayerModel.markEvicted(url)` переводит его в `.remote` в очереди, чтобы следующий play скачал заново. *Решение моё.*
- Ошибку `evict`/`start…` показываем тем же `alert`, что и ошибку скачивания в v1.

### 5. Скорость

- `PlayerModel.rate: Float`, значения по кругу: 1 → 1,25 → 1,5 → 2 → 0,75 → 1. Сохраняется в `UserDefaults` (ключ `rate`), применяется ко всем трекам.
- `AudioEngine` получает `var rate: Float { get set }`; `AVAudioPlayerEngine`: `enableRate = true` до `prepareToPlay()`, `rate` выставляется при `load` и при смене. Тон сохраняется — `AVAudioPlayer` сам.
- `NowPlaying`: `MPNowPlayingInfoPropertyPlaybackRate = rate` пока играет (иначе прогресс на локскрине уедет).
- В Now Playing — кнопка с текстом «1×», «1,25×», «1,5×», «2×», «0,75×» (русская запятая, как в интерфейсе). Нижний ряд Now Playing: скорость — `RoutePicker` — таймер сна.

## Не делаем

- Плавные переходы / кроссфейд (отложены), gapless, эквалайзер.
- Позиция внутри файла, «продолжить главу» по папке.
- Скорость по папкам, ползунок скорости, произвольные минуты таймера.
- Затухание при срабатывании таймера.
- Выгрузка/скачивание рекурсивно по дереву папок.
- Переименование папки «Siply».

## Ограничения

Те же, что в v1: iOS 26.1+, SwiftUI, AVFoundation, ноль зависимостей, XcodeGen, тесты на симуляторе iPhone 17. Репо `art-ps/siply-ios`, ветка `main`, без pull request'ов.

## Критерии приёмки (тесты)

Unit (`xcodebuild test -scheme Siply -destination 'platform=iOS Simulator,name=iPhone 17'`), `PlayerModel` — с `FakeAudioEngine`, `FakeDownloader` и отдельным `UserDefaults(suiteName:)`:

1. **Сохранение.** `play(queue: [A, B, C], startingAt: 1)`, `seek(to: 17)`, `togglePlayPause()` → в defaults `playback`: `urls == [A, B, C]`, `currentIndex == 1`, `position == 17`. Ключ пишется только при непустой очереди: новый `PlayerModel`, ничего не играл → ключа нет; неудачное `restore` ключ не меняет.
2. **Восстановление.** Новый `PlayerModel` на тех же defaults, `restore(resolving:)` с фейком, у которого A, B, C существуют → `currentTrack == B`, `currentTime == 17`, `isPlaying == false`, `engine.load(B)` вызван, `engine.play` — нет.
3. **Пропавший файл.** Файл B (текущий) не существует → очередь пуста, `currentTrack == nil`. Файл C не существует, B есть → очередь `[A, B]`, текущий B.
4. **Нескачанный текущий.** B `.remote` → восстановлен как текущий, `engine.load` не вызван, `currentTime == 0`; `togglePlayPause()` → `downloader.download(B)` вызван, после завершения — `load` и `play`.
5. **Таймер сна.** `sleep = .minutes(15)` → `sleepDeadline` в пределах 15 мин ± 1 с от «сейчас». `tick(now: deadline)` при игре → `isPlaying == false`, `sleep == .off`. `tick(now: deadline - 1)` → играет. `sleep = .endOfTrack`, трек доиграл (`engine.onFinished`) → `isPlaying == false`, текущий трек тот же, `currentTime == 0`, `sleep == .off`. `sleep = .off` после `.minutes` → `sleepDeadline == nil`.
6. **Переименование.** `store.rename(source, to: "  Книги ")` → `name == "Книги"`, после пересоздания store на тех же defaults имя сохранилось. `rename(source, to: "   ")` → имя прежнее. `displayName` для URL с последним компонентом-UUID → «Папка».
7. **Выгрузка в очереди.** Играет A из `[A, B]`; `markEvicted(B)` → `queue[1].download == .remote`; `next()` → `download(B)` вызван до `load`. `markEvicted(A)` (текущий) → состояние A не меняется.
8. **Скорость.** `rate` по умолчанию 1; `cycleRate()` ×5 даёт 1,25 → 1,5 → 2 → 0,75 → 1; каждое значение уходит в `engine.rate` и в defaults `rate`; новый `PlayerModel` на тех же defaults стартует с сохранённым значением и выставляет его в `engine`.
9. **Действия по файлу.** `FileAction.available(isUbiquitous: Bool, state: DownloadState) -> Set<FileAction>`: не iCloud → `[]`; iCloud `.local` → `[.evict]`; `.remote` → `[.download]`; `.downloading`/`.onDemand` → `[]`. `FileAction.available(isUbiquitous:folderState:fileStates:)` для папки: папка сама `.remote` → `[.download]`; иначе по состояниям прямых файлов — `.download`, если есть `.remote`; `.evict`, если есть `.local`; оба — если есть оба; не iCloud → `[]`.

Руками на устройстве (дописать в `docs/checklist.md`):

10. Играет глава из iCloud, закрыл приложение свайпом, открыл → мини-плеер с той же главой, на паузе, ползунок на месте; play — продолжает.
11. Таймер «15 мин» → через 15 минут пауза; «До конца трека» → после конца трека тишина, плеер на том же треке.
12. Долгое нажатие на источник → переименовал → имя осталось после перезапуска. Подпапка «На iPhone» добавляется как «Папка».
13. Свайп по скачанному iCloud-треку → «Удалить с устройства» → трек серый, в Files тоже с облаком; свайп → «Скачать» → белеет. Долгое нажатие на папку → «Удалить с устройства» → папка серая. На треке в папке «Siply» свайпа нет.
14. Скорость 1,25× — речь быстрее, тон тот же; локскрин показывает прогресс верно; после перезапуска 1,25× осталась.

## На усмотрение исполнителя

- Где хранить `PlaybackState` и логику восстановления: внутри `PlayerModel` или отдельный `PlaybackStore`; как инъецировать проверку существования файла и загрузку тегов в тесты.
- Как перезапускать `watchDownloads()` после свайпа «Скачать» (ключ `.task(id:)`, флаг, `.onChange`).
- Формат остатка таймера сна и где именно он стоит в Now Playing.
- Оформление кнопки скорости (капсула, `.buttonStyle(.bordered)` и т.п.).
