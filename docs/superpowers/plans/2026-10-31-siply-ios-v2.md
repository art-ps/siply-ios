# Siply iOS v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Пять функций поверх v1: скорость воспроизведения, таймер сна, продолжение после перезапуска, переименование источника, скачивание/выгрузка iCloud-файлов из списка.

**Architecture:** Всё состояние плеера остаётся в `PlayerModel` (`@Observable`, `@MainActor`), новые поля сохраняются в тот же `UserDefaults`, что `volume`/`shuffle`. Движок `AudioEngine` получает `rate`. Действия над файлами — чистая функция `FileAction.available` + обработчики в `FolderView`. UI — Now Playing (скорость, таймер), `SourcesView` (переименование), `FolderView` (свайп и меню папки).

**Tech Stack:** Swift 5, SwiftUI, AVFoundation (`AVAudioPlayer.enableRate`), MediaPlayer, XCTest. XcodeGen, тесты на симуляторе `iPhone 17`.

**Spec:** `docs/superpowers/specs/2026-10-31-siply-ios-v2-design.md`

## Global Constraints

- iOS 26.1+, ноль сторонних зависимостей, XcodeGen (`project.yml`; новые файлы в `Siply/` и `SiplyTests/` подхватываются автоматически, после добавления файлов — `xcodegen generate`).
- Тесты: `xcodebuild test -scheme Siply -destination 'platform=iOS Simulator,name=iPhone 17'`. Перед коммитом — все 87+ зелёные.
- Ветка `main`, репо `art-ps/siply-ios`. Коммиты на русском, без Co-Authored-By. Pull request'ы не создаём.
- Тексты интерфейса — русские, числа с запятой («1,25×»).
- Стиль: как в существующем коде — короткие комментарии «почему», без лишних абстракций (`ponytail`).
- Сборку на устройство делает контролёр, не задачи.

## Review Focus

1. Восстановление очереди, где текущий трек `.local`, но `engine.load` бросил (файл битый): плеер не должен остаться с `currentTrack` и нулевой длиной навсегда — ожидание: очередь восстановлена, `currentTime == 0`, следующий `play` идёт по обычному пути `playTrack` (тест в Task 3).
2. Сохранение состояния в середине `playAfterDownload` (трек `.remote`): `position` должна быть 0, не хвост старого трека (тест в Task 3).
3. Таймер сна «До конца трека» при `repeatMode == .one`: трек не должен перезапуститься (тест в Task 2).
4. Выгрузка файла, который сейчас играет: пропускается, очередь не трогается (тест в Task 5).
5. Свайп «Скачать» в папке, где `watchDownloads()` уже завершился (все были белые, потом один выгрузили): строка должна побелеть без перезахода (ручной пункт чеклиста 13, Task 5 перезапускает наблюдатель по ключу).
